# Тип заказчика заявки

В запросах создания и изменения заявки используется `customer_type`: `internal` — внутренний заказчик, `representative` — внешний заказчик через представителя института, `external` — внешний заказчик. Неизвестное значение возвращает HTTP 400. Без обоих полей типа при создании используется `external`; при PATCH тип сохраняется.

Поле `is_internal_customer` сохраняется для совместимости и равно `true` только для `internal`. Старый клиент может отправить его вместо нового: `true` установит `internal`, `false` — `external`. Поэтому явный `false` заменит тип `representative`. Если одновременно переданы противоречащие поля, API возвращает HTTP 400.

В ответах используется `customer_type` либо `customerType` в зависимости от соглашения конкретного API. В статистике проектов поле `type` также принимает три значения. Фильтр dashboard `application_type` принимает `all`, `internal`, `external`, `representative` и отбирает каждый тип отдельно. Показатель доли внешних включает оба типа `external` и `representative`; распределение по типам показывает их раздельно.

`is_external` — независимый признак маршрута подачи заявки и не изменяется при изменении типа заказчика. Миграция преобразует старое `is_internal_customer=true` в `internal`, а `false` в `external`; исторических представителей по старому полю распознать нельзя.
