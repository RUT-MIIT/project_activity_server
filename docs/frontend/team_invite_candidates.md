# Приглашение в команду по треку — API для фронта

Базовый префикс: `/api/teams/my-team/`

**Доступ:** студент с учебной группой; поиск и отправка приглашений — только капитану команды в статусе `forming`.

**Авторизация:** `Authorization: Bearer <token>`
**Формат полей ответа:** camelCase.

---

## Что изменилось

- Состав команды ограничивается **проектным треком**, а не учебной группой.
- `home_study_group` у команды остаётся группой капитана (информационно).
- В лобби список команд по-прежнему только своей группы; межгрупповой набор — через приглашения.
- `tracks[].teamsCount` / `canCreateTeam` считаются по **всем командам трека** (все группы), а не только своей.
- При создании команды в лобби трек обязателен (если у группы ровно один трек — подставится автоматически).

## Поиск кандидатов

```http
GET /api/teams/my-team/invite-candidates/?q=Ива&limit=20&semester_id=actual
```

### Query-параметры

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `q` | `string` | да | Кусок ФИО; токены через пробел, каждый ≥ 2 символов (регистр не важен, в т.ч. кириллица) |
| `limit` | `number` | нет | Лимит результатов (по умолчанию 20, максимум 50) |
| `semester_id` | `number` \| `"actual"` \| `"next"` | нет | Семестр (по умолчанию `actual`) |

### Ответ `200`

```json
{
  "trackId": 5,
  "scope": "track",
  "results": [
    {
      "id": 120,
      "user_id": 34,
      "full_name": "Иванов Иван Иванович",
      "group": { "id": 3, "name": "УВП-211" },
      "isRegistered": true,
      "inTeam": false,
      "team": null,
      "hasPendingInvitation": false,
      "canInvite": true
    },
    {
      "id": 88,
      "user_id": null,
      "full_name": "Иванушкин Незарег",
      "group": { "id": 4, "name": "УВП-212" },
      "isRegistered": false,
      "inTeam": false,
      "team": null,
      "hasPendingInvitation": false,
      "canInvite": false
    }
  ]
}
```

| Поле | Описание |
|------|----------|
| `trackId` | Трек команды; `null` для legacy-команд без трека |
| `scope` | `"track"` — все группы трека; `"group"` — fallback на home-группу |
| `id` | ID предрегистрации или `user.id` (как в контингенте) |
| `user_id` | ID пользователя в системе; `null`, если ещё не зарегистрирован |
| `isRegistered` | Есть полноценный аккаунт (не placeholder) |
| `inTeam` | Уже состоит в команде в этом семестре |
| `team` | Снимок команды, если `inTeam` |
| `hasPendingInvitation` | Уже есть pending-приглашение от этой команды |
| `canInvite` | Можно ли отправить приглашение сейчас |

Пригласить можно только если `canInvite === true` (нужен `user_id`).

### Ошибки

| Статус | Когда |
|--------|-------|
| `400` | Короткий `q`, нет команды, состав уже подтверждён |
| `403` | Не капитан / не студент |

## Отправка приглашения

```http
POST /api/teams/my-team/invitations/
Content-Type: application/json

{
  "user_id": 34,
  "role": "member"
}
```

Сценарий на фронте:

1. `GET /invite-candidates/?q=...`
2. Пользователь выбирает строку с `canInvite: true`
3. `POST /invitations/` с `user_id` из ответа
4. Приглашённый принимает через `POST /api/teams/lobby/invitations/{id}/accept/`

### Ошибки приглашения

| Сообщение | Причина |
|-----------|---------|
| Студент должен быть из группы вашего проектного трека | Группа не в треке команды |
| Студент не зарегистрирован в системе | Placeholder / нет аккаунта |
| Студент уже состоит в команде | Уже занят в семестре |
| Приглашение этому студенту уже отправлено | Дубль pending |

---

## Лобби: семантика слотов

В `GET /api/teams/lobby/`:

- `tracks[].teams` — только команды **своей** группы в треке;
- `tracks[].teamsCount` — число команд **всего трека** (все группы);
- `tracks[].canCreateTeam` — сравнение `teamsCount` с `recommendedTeamsCount` трека.
