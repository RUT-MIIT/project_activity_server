# Quickdraw команды

Одна доска соответствует `my_team.id` из ответа учебной группы или `my-team`. Это ID команды в семестре. Если у студента нет команды, оставьте доску локальной и не открывайте сокет.

## REST

`GET /api/teams/my-team/board/` возвращает `{"snapshot":{"document":{"store":{}}}}` для новой доски. Передавайте `Authorization: Bearer <accessToken>`. Если команда выбрана для конкретного семестра, передавайте тот же `?semester_id=<id>` при GET и PUT. Без параметра используется текущий семестр (`actual`).

`PUT /api/teams/my-team/board/` с `Content-Type: application/json` принимает `{"snapshot":{...}}` и отдаёт сохранённый объект в том же конверте. Последний успешный PUT заменяет полный снимок. Сохраняйте актуальный snapshot после паузы около секунды, включая принятые remote-правки. Держите не более одного PUT в полёте на вкладку.

Ответы API: 401 — нужен действительный токен, 403 — нет членства, 400 — неверный JSON или формат snapshot, 413 — тело больше 8 МиБ.

## WebSocket

Подключайтесь к `wss://<host>/ws/teams/<my_team.id>/board/?token=<encodedAccessToken>`. Сначала загрузите `snapshot` из сообщения с `clientId: "server"`, затем включите отправку своих правок. Первого серверного сообщения достаточно для старта. При reconnect заново загрузите первый snapshot. Снимок содержит последние сохранённые данные, поэтому события, разосланные до подключения и ещё не записанные в БД, могут в нём отсутствовать.

Отправляйте непустые правки из `store.listen(..., { source: 'user' })` в виде `{"type":"diff","clientId":"<uuid вкладки>","diff":{"added":{},"removed":{},"updated":{}}}`. У получателя передайте `diff` в `store.applyDiff(diff, 'remote')`. Сервер сохраняет исходный `clientId` и исключает только отправившее подключение. Сообщение ограничено 512 КиБ. Если добавление изображения превышает лимит WS, оно доступно в сохранённом snapshot после загрузки.

Запрос `{"type":"hello","clientId":"<uuid вкладки>"}` выдаёт новый снимок только запросившему подключению. Отправляйте его лишь при намеренной повторной загрузке: снимок может предшествовать полученным живым правкам. Сохранение выполняется через PUT.

## Развёртывание

1. Установите зависимости и примените миграции. Настройте `BOARD_REDIS_URL` (по умолчанию `redis://127.0.0.1:6379/0`) и `BOARD_ALLOWED_ORIGINS` (точные origin фронта через запятую, включая схему и порт при необходимости). Пустой список запрещает подключения.
2. Используйте `deploy/quickdraw-board.service` как шаблон. Подставьте реальные пути и пользователя существующего сервиса, установите unit и запустите его через systemd. REST остаётся на текущем Gunicorn.
3. Подключите `deploy/quickdraw-board.nginx.conf` внутри существующего TLS server block, сохранив настройки основного upstream. Проверьте `nginx -t` перед reload. Для `/ws/` отключены nginx access/error logs и access logs Uvicorn, поскольку query string содержит JWT. Проверьте, что внешний прокси также его не журналирует.
4. Проверьте PUT через прокси и обмен diff между соединениями, открытыми на двух ASGI-процессах с одним Redis. После PUT переподключение должно вернуть сохранённый снимок.
