# Quickdraw команды

Одна доска соответствует `my_team.id` из ответа учебной группы или `my-team`. Это ID команды в семестре. Если у студента нет команды, оставьте доску локальной и не открывайте сокет.

## REST

`GET /api/teams/my-team/board/` возвращает `{"snapshot":{"document":{"store":{}}}}` для новой доски. Передавайте `Authorization: Bearer <accessToken>`. Если команда выбрана для конкретного семестра, передавайте тот же `?semester_id=<id>` при GET и PUT. Без параметра используется текущий семестр (`actual`).

`PUT /api/teams/my-team/board/` с `Content-Type: application/json` принимает `{"snapshot":{...}}` и отдаёт сохранённый объект в том же конверте. До первой правки через WebSocket PUT может загрузить исходный снимок. После первой сохранённой правки PUT возвращает текущий снимок, чтобы автосохранение старой вкладки не затёрло правки. Клиент протокола 2 сохраняет только через WebSocket.

Ответы API: 401 — нужен действительный токен, 403 — нет членства, 400 — неверный JSON или формат snapshot, 413 — тело больше 8 МиБ.

## WebSocket

Подключайтесь к `wss://<host>/ws/teams/<my_team.id>/board/?token=<encodedAccessToken>&sync=2`. Сервер присылает `snapshot` с `protocol: 2` и номером сохранённой ревизии. При переподключении загрузите присланный снимок и повторите неподтверждённые локальные изменения.

Клиент объединяет изменения примерно за 50 мс и отправляет один `edit` с `clientId`, `sequence` и `changes`. В `changes.records` передаются изменённые записи целиком, в `changes.removed` — их идентификаторы, в `changes.strokes` — добавленные тройки координат и давления, смещение в массиве точек и флаг завершения штриха. Сервер сохраняет правку в транзакции, возвращает автору `ack` с `sequence` и `revision` и рассылает правку остальным клиентам. Каждый кадр ограничен 512 КиБ. Крупные правки, например вставка изображения, передаются несколькими кадрами `edit-chunk`. Получатели крупной правки запрашивают новый снимок после сообщения `invalidate`.

Запрос `{"type":"hello","clientId":"<uuid вкладки>"}` выдаёт новый снимок только запросившему подключению. Он нужен после пропуска ревизии. При конфликте смещения штриха сервер присылает снимок с полем `retry`, после чего клиент повторяет правку целой записью. Клиенты без `sync=2` продолжают отправлять и получать сообщения `diff`. Чтобы передавать изображения больше 512 КиБ, старые вкладки нужно обновить.

## Развёртывание

1. Установите зависимости и примените миграции. Настройте `BOARD_REDIS_URL` (по умолчанию `redis://127.0.0.1:6379/0`) и `BOARD_ALLOWED_ORIGINS` (точные origin фронта через запятую, включая схему и порт при необходимости). Пустой список запрещает подключения.
2. Используйте `deploy/quickdraw-board.service` как шаблон. Подставьте реальные пути и пользователя существующего сервиса, установите unit и запустите его через systemd. REST остаётся на текущем Gunicorn.
   `update_prod.sh` перезапускает установленный `quickdraw-board.service` вместе с Gunicorn. Если unit доски называется иначе, задайте `BOARD_SERVICE` в `.env`.
3. Подключите `deploy/quickdraw-board.nginx.conf` внутри существующего TLS server block, сохранив настройки основного upstream. Проверьте `nginx -t` перед reload. Для `/ws/` отключены nginx access/error logs и access logs Uvicorn, поскольку query string содержит JWT. Проверьте, что внешний прокси также его не журналирует.
4. Проверьте обмен правками между соединениями, открытыми на двух ASGI-процессах с одним Redis. После `ack` переподключение должно вернуть сохранённый снимок без ожидания автосохранения.
