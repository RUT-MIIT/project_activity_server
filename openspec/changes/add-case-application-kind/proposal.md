# Proposal

## Why

Система сейчас поддерживает только обычную проектную заявку с четырьмя отдельными полями описания проблемы. Нужен второй вид «Заявка-кейс» с единым описанием кейса и единообразной выдачей новых полей в API.

## What Changes

- Добавить в заявку поле `application_kind` со значениями `project` и `case`; для существующих и новых заявок по умолчанию использовать `project`.
- Добавить единое текстовое поле `case_description` с отображаемым названием «Кейс».
- Для `case` требовать непустой `case_description`, а `problem_holder`, `goal`, `barrier` и `existing_solutions` считать необязательными.
- Для `project` сохранить текущие правила обязательности и валидации четырёх полей.
- При смене вида заявки не очищать ни `case_description`, ни четыре существующих поля; выбор показываемых полей остаётся за фронтендом.
- Во все записе-ориентированные API-ответы, где выдаётся заявка или её краткое представление, добавить оба новых поля с соблюдением текущего snake_case или camelCase контракта endpoint.
- Не переопределять существующие `application_type` в dashboard и `type` в stats API, которые уже обозначают внутреннего/внешнего заказчика.

## Capabilities

### New Capabilities

- `application-kinds`: Виды проектных заявок, условная валидация заявки-кейса, сохранение данных при смене вида и выдача новых полей в API.

### Modified Capabilities

- `institute-responsible-mentors-stats` — дополнить вложенные проекты в деталях наставника.
- `institute-responsible-students-stats` — дополнить вложенные проекты в статистике и операционном списке студентов.

## Impact

- Модель `ProjectApplication` и новая Django-миграция с безопасными значениями по умолчанию.
- Create/update serializers, DTO, domain validation, repository persistence and Django admin.
- Ответные DTO в `showcase` и вложенные представления проекта в `teams`, включая витрины, треки, группы, команды и статистику.
- API-схемы, документация и автотесты для create/update/read/list и вложенных API-ответов.
- Новых внешних зависимостей нет; изменение аддитивное для ответов и обратно совместимо для существующих записей.
