# Spec Delta

## Purpose

Позволяет студентам одной команды рисовать вместе с разных устройств и восстанавливать последнее сохранённое состояние доски.

## ADDED Requirements

### Requirement: Доступ к снимку команды

API SHALL предоставлять GET и PUT `/api/teams/my-team/board/` студентам с действительным Bearer access JWT и членством в команде, выбранной по тем же правилам `semester_id`, что у `my-team`. Без членства API SHALL возвращать 403, без действительного JWT — 401.

#### Scenario: Новая доска

- **WHEN** участник запрашивает доску, которую ещё не сохраняли
- **THEN** API возвращает 200 и `{"snapshot":{"document":{"store":{}}}}`

#### Scenario: Два сохранения

- **WHEN** участники последовательно отправляют два PUT с JSON-объектом в поле `snapshot`
- **THEN** оба запроса возвращают 200, а последующий GET возвращает второй объект целиком, без интерпретации содержимого

#### Scenario: Недопустимый запрос

- **WHEN** тело PUT превышает 8 МиБ либо укладывается в лимит, но содержит некорректный JSON или поле `snapshot` отсутствует либо не является объектом
- **THEN** API возвращает соответственно 413 или 400 и сохраняет прежнее состояние доски

### Requirement: Комната команды

WebSocket `/ws/teams/<team_id>/board/?token=<accessToken>` SHALL принимать подключения только участников указанной команды с действительным access JWT и разрешённым Origin. На connect и на `{"type":"hello","clientId":"..."}` сервер SHALL отправлять этому подключению `{"type":"snapshot","clientId":"server","snapshot":{...}}` с последним сохранённым состоянием или той же пустой доской, что у REST.

#### Scenario: Переподключение после сохранения

- **WHEN** GET или успешный PUT подтверждает сохранённое состояние и участник заново подключается к комнате
- **THEN** первым сообщением он получает этот snapshot, если более новое сохранение не заменило его

#### Scenario: Чужая комната

- **WHEN** пользователь другой команды, клиент с недействительным JWT или браузер с неразрешённым Origin пытается подключиться
- **THEN** сервер отклоняет подключение до выдачи snapshot и подписки на комнату

### Requirement: Передача живых правок

Сервер SHALL пересылать сообщение `diff` со строковым `clientId` и объектом `diff`, содержащим объекты `added`, `removed` и `updated`, только остальным подключениям комнаты. Сервер SHALL сохранять исходный `clientId` и содержимое `diff`. Сохранение доски SHALL выполняться через REST PUT.

#### Scenario: Два участника

- **WHEN** первое из двух подключений одной команды отправляет корректный `diff`
- **THEN** второе получает этот `diff`, первое не получает эхо, другие комнаты не получают сообщение, а REST snapshot не меняется

#### Scenario: Клиент отправляет snapshot

- **WHEN** клиент отправляет сообщение `snapshot` через WebSocket
- **THEN** сервер не сохраняет и не пересылает его
