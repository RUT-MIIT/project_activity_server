# Spec Delta

## Purpose

Описывает API статистики наставников для ответственного института: лёгкий список нагрузки и детальная карточка с контингентом и командами по группам в семестре.

## ADDED Requirements

### Requirement: Список наставников по доступным институтам

Система SHALL предоставлять аутентифицированным пользователям с ролью `institute_validator`, `cpds`, `admin` либо `is_staff` эндпоинт `GET /api/teams/institute-responsible/mentors/`, который возвращает массив наставников для аналитики.

Система MUST требовать query-параметр `semester_id` (числовой id либо `actual` / `next`). При отсутствии параметра система MUST отвечать HTTP 400.

Система SHALL включать в список только пользователей с `role.code == "mentor"`, у которых подразделение входит в дерево подразделений **всех доступных** институтов вызывающего (для `cpds` / `admin` / `staff` — все активные институты; для `institute_validator` — институты его подразделения). Параметр `institute_code` для этого эндпоинта не обязателен и не сужает выборку по умолчанию: фильтрация по институту выполняется на клиенте по полю `institute` в ответе.

Система SHALL включать наставников без назначенных учебных групп в указанном семестре (пустой массив `groups`, `teamsCount = 0`).

Каждый элемент списка MUST содержать:

- `id` (number) — id пользователя;
- `fullName` (string);
- `institute` — объект `{ id: string, name: string }`, где `id` равен `Institute.code`, а институт определяется по подразделению наставника;
- `groups` — массив `{ id, name, studentsCount }` учебных групп, где пользователь назначен наставником в `StudyGroupSemester` для запрошенного семестра; `studentsCount` — размер контингента группы (предрегистрация + прямые студенты без двойного учёта), как в обзоре групп наставника;
- `teamsCount` (number) — суммарное число `TeamSemester` в этом семестре у домашних групп из `groups` наставника (0, если групп нет).

Система MUST NOT включать в ответ поле статуса нагрузки (`loadStatus` / аналоги): его считает клиент.

Система MUST выполнять выборку без N+1 (число SQL-запросов не растёт пропорционально числу наставников или групп).

#### Scenario: Успешный список для ответственного института

- **WHEN** пользователь с ролью `institute_validator` запрашивает `GET .../mentors/?semester_id=actual`
- **THEN** система возвращает HTTP 200 и массив наставников с `role=mentor` только по институтам, доступным этому пользователю, включая записи с пустым `groups`

#### Scenario: cpds видит наставников всех институтов

- **WHEN** пользователь с ролью `cpds` запрашивает `GET .../mentors/?semester_id=<id>`
- **THEN** система возвращает наставников по всем активным институтам

#### Scenario: semester_id обязателен

- **WHEN** клиент вызывает `GET .../mentors/` без `semester_id`
- **THEN** система возвращает HTTP 400 с описанием ошибки

#### Scenario: Наставник без групп в списке

- **WHEN** в институте есть пользователь с ролью `mentor` без записей в `StudyGroupSemester.mentors` для семестра
- **THEN** он присутствует в ответе с `groups: []` и `teamsCount: 0`

### Requirement: Детальная карточка наставника

Система SHALL предоставлять `GET /api/teams/institute-responsible/mentors/{id}/` с обязательным `semester_id`.

Система MUST вернуть HTTP 404, если пользователь с таким id не найден, не имеет роли `mentor`, либо его институт не входит в доступные вызывающему.

При успехе ответ MUST содержать те же поля верхнего уровня, что и элемент списка (`id`, `fullName`, `institute`, `teamsCount`), а `groups` MUST быть массивом детальных групп:

- `id`, `name`;
- `students` — полный контингент группы в формате stats-студента;
- `teams` — команды группы в семестре в формате stats-команды.

Stats-студент MUST содержать: `id`, `fullName`, `institute` (`{ id: string, name }`), `studyGroup` (`{ id, name }`), `course` (номер курса группы), `isRegistered`, `team` (`{ id, name } | null`), `project` (`{ id, name } | null`).  
`team.id` и id команды в `teams` MUST быть id записи `TeamSemester`.  
`project.name` MUST заполняться из названия заявки (`ProjectApplication.title`).

Stats-команда MUST содержать: `id`, `name`, `status`, `project` (`{ id, name } | null`), `studyGroup` (`{ id, name }`), `members` (массив stats-студентов — участников команды), `membersCount`.

Система MUST выполнять сборку detail без N+1 по группам, студентам и участникам команд.

#### Scenario: Успешная деталь с группами

- **WHEN** ответственный запрашивает detail наставника, у которого в семестре есть группы со студентами и командами
- **THEN** система возвращает HTTP 200, в каждой группе заполнены `students` и `teams`, у команд заполнены `members` и `membersCount`

#### Scenario: Нет доступа к институту наставника

- **WHEN** `institute_validator` запрашивает detail наставника другого института
- **THEN** система возвращает HTTP 404

#### Scenario: Наставник без групп в detail

- **WHEN** запрашивается detail наставника без назначений в семестре
- **THEN** система возвращает HTTP 200 с `groups: []` и `teamsCount: 0`

### Requirement: Права доступа к API наставников статистики

Система MUST применять те же правила доступа, что и к остальному API `institute-responsible`: только `institute_validator`, `cpds`, `admin` или `is_staff`. Неавторизованный либо недопущенный пользователь MUST получать отказ в доступе.

#### Scenario: Студент не имеет доступа

- **WHEN** пользователь с ролью `student` вызывает `GET .../mentors/?semester_id=actual`
- **THEN** система отказывает в доступе (HTTP 403)
