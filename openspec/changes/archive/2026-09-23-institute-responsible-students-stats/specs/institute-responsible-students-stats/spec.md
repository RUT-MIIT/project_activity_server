# Spec Delta

## Purpose

Описывает API списка студентов для дашборда ответственного института: multi-institute контингент в формате stats-студента с наставниками группы в семестре.

## ADDED Requirements

### Requirement: Список студентов по доступным институтам

Система SHALL предоставлять аутентифицированным пользователям с ролью `institute_validator`, `cpds`, `admin` либо `is_staff` эндпоинт `GET /api/teams/institute-responsible/students-stats/`, который возвращает массив студентов контингента для аналитики.

Система MUST требовать query-параметр `semester_id` (числовой id либо `actual` / `next`). При отсутствии параметра система MUST отвечать HTTP 400.

Система SHALL включать контингент активных (`is_end=False`) учебных групп, у которых `institute_id` входит в множество **всех доступных** институтов вызывающего (для `cpds` / `admin` / `staff` — все активные институты; для `institute_validator` — институты его подразделения). Контингент MUST собираться так же, как в операционном списке студентов института: предрегистрация (`PreRegisteredStudent`) и напрямую созданные студенты (`User` с `study_group`, без записи предрегистрации), без двойного учёта.

Параметр `institute_code` для этого эндпоинта не обязателен и не сужает выборку по умолчанию: фильтрация по институту и курсу выполняется на клиенте по полям `institute` и `course`.

Система MUST NOT изменять контракт существующих эндпоинтов `GET .../students/` и `GET .../students/export/`.

Система MUST NOT предоставлять detail-эндпоинт `students-stats/{id}` в рамках этой capability.

Каждый элемент списка MUST содержать:

- `id` (number) — id записи контингента: id предрегистрации либо id пользователя для студента без предрегистрации (как в операционном списке);
- `fullName` (string) — ФИО через пробел (пустые части пропускаются);
- `institute` — объект `{ id: string, name: string }`, где `id` равен `Institute.code` группы студента;
- `studyGroup` — объект `{ id: number, name: string }` учебной группы;
- `course` (number) — `StudyGroup.course_number`;
- `isRegistered` (boolean) — полная регистрация (есть user, не placeholder), как в операционном контингенте;
- `team` — `{ id: number, name: string } | null`, где `id` — id записи `TeamSemester` в запрошенном семестре (если студент состоит в команде), иначе `null`;
- `project` — `{ id: number, name: string } | null`, где `name` заполняется из `ProjectApplication.title` выбранной заявки команды; `null`, если команды или заявки нет;
- `mentors` — массив `{ id: number, fullName: string }` наставников учебной группы студента в `StudyGroupSemester` для запрошенного семестра (пусто, если наставников нет).

Система MUST NOT включать в ответ вычисляемые KPI дашборда (общий контингент, доли зарегистрированных / в командах / с проектом): их считает клиент.

Система MUST выполнять выборку без N+1 (число SQL-запросов не растёт пропорционально числу студентов, групп или наставников).

#### Scenario: Успешный список для ответственного института

- **WHEN** пользователь с ролью `institute_validator` запрашивает `GET .../students-stats/?semester_id=actual`
- **THEN** система возвращает HTTP 200 и массив студентов только по институтам, доступным этому пользователю, в формате stats-студента с полем `mentors`

#### Scenario: cpds видит студентов всех институтов

- **WHEN** пользователь с ролью `cpds` запрашивает `GET .../students-stats/?semester_id=<id>`
- **THEN** система возвращает студентов контингента по всем активным институтам

#### Scenario: semester_id обязателен

- **WHEN** клиент вызывает `GET .../students-stats/` без `semester_id`
- **THEN** система возвращает HTTP 400 с описанием ошибки

#### Scenario: Студент без команды и без проекта

- **WHEN** в доступном институте есть студент контингента без членства в `TeamSemester` в запрошенном семестре
- **THEN** он присутствует в ответе с `team: null` и `project: null`

#### Scenario: Наставники группы в семестре

- **WHEN** у учебной группы студента в `StudyGroupSemester` назначены наставники
- **THEN** в элементе ответа `mentors` содержит их `id` и `fullName`

#### Scenario: Операционный список студентов не изменился

- **WHEN** клиент запрашивает `GET .../students/?semester_id=actual`
- **THEN** структура ответа остаётся прежней (раздельное ФИО, `teamName`/`teamRole`, `project.title` и т.д.) и не обязана совпадать с `students-stats`

### Requirement: Права доступа к students-stats

Система MUST применять те же правила доступа, что и к остальному API `institute-responsible`: только `institute_validator`, `cpds`, `admin` или `is_staff`. Неавторизованный либо недопущенный пользователь MUST получать отказ в доступе.

#### Scenario: Студент без прав

- **WHEN** пользователь с ролью студента вызывает `GET .../students-stats/?semester_id=actual`
- **THEN** система возвращает HTTP 403
