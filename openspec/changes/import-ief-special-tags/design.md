# Design

## Context

`import_tags` удаляет все теги и связи с заявками. Модель `Tag` поддерживает категорию, признак базового тега и множество подразделений; институт IEF ссылается на подразделение. API тегов показывает пользователям теги их подразделения и непосредственного родителя.

## Goals / Non-Goals

**Goals:** Доставить исходный документ вместе с проектом и предоставить повторяемую отдельную команду без изменения существующих данных.

**Non-Goals:** Замена общего импорта, синхронизация удалённых из документа тегов, изменение API или модели данных.

## Decisions

- Хранить DOCX в проекте и читать его при запуске; разбирать последовательность абзацев, где заголовок задаёт категорию для последующих строк с `#`. Документ на момент анализа содержит 17 разделов и 94 строки тегов. Проверять структуру до записи. Альтернатива — отдельный CSV, но он создаёт второй источник данных.
- Использовать код `IEF` и `Institute.department`, не фиксируя ID подразделения. При отсутствии привязки завершать команду ошибкой.
- Идентифицировать существующий тег по имени без учёта регистра и связи с подразделением IEF. Существующие записи не изменять; это сохраняет их категории и все связи. Совпадение общего тега или тега другого подразделения не заменяет отдельный тег ИЭФ.
- Сохранение выполнять атомарно и сообщать результаты. Не вызывать существующую команду, поскольку она удаляет данные. Проверить зависимости: стандартные средства чтения DOCX позволяют избежать новой runtime-зависимости, если это соответствует структуре файла.

## Risks / Trade-offs

- [Формат документа изменится] → проверять категории, названия и ошибки чтения до изменения БД.
- [Глубокая иерархия подразделений] → действующая фильтрация тегов учитывает только подразделение и непосредственного родителя; не расширять её без отдельного требования.
- [Тег с тем же именем уже привязан к IEF и имеет другую категорию] → пропустить его без изменения и сообщить в итоговой статистике.

## Migration Plan

Развернуть документ и команду, убедиться в наличии связанного подразделения IEF, затем запустить команду вручную. Автоматического импорта при развёртывании нет. Для отката требуется отдельно оценить созданные теги и их новые связи с заявками; автоматическое удаление не предусмотрено.
