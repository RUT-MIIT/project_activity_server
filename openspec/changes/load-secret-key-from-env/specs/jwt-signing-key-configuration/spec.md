# Spec Delta

## Purpose

Определяет безопасную конфигурацию ключа подписи токенов, чтобы сервер принимал только токены, подписанные действующим секретом окружения, и не запускался без него.

## ADDED Requirements

### Requirement: Signing key comes from the environment

Система SHALL использовать значение `SECRET_KEY`, переданное через окружение процесса или локальный `.env`, как ключ подписи JWT. Система MUST NOT использовать ключ, зашитый в исходный код или сценарий развёртывания.

#### Scenario: Configured signing key

- **WHEN** приложение запускается с непустым `SECRET_KEY` в окружении
- **THEN** приложение запускается и проверяет JWT с этим ключом

#### Scenario: Missing signing key

- **WHEN** приложение запускается без `SECRET_KEY` или с пустым значением
- **THEN** запуск завершается с понятной ошибкой конфигурации, не раскрывающей значение ключа

### Requirement: Rotated key rejects old tokens

Система SHALL отклонять JWT, подписанный предыдущим ключом, после запуска с новым `SECRET_KEY`.

#### Scenario: Previously issued access token

- **WHEN** клиент отправляет access-токен, подписанный предыдущим ключом, после смены `SECRET_KEY`
- **THEN** защищённый API отклоняет токен и требует повторной авторизации
